# Запуск на BotHost

Код обновляется из GitHub. Переменные владельца задаются в панели BotHost. Очередь, кабинеты и их настройки хранятся на постоянном диске. Перед сменой параметров сделай резервную копию текущей папки данных и проверь, куда она смонтирована.

## Приватный репозиторий

В GitHub создай fine-grained token владельца репозитория. Выбери только нужный репозиторий и разрешение **Contents → Read-only**.

В BotHost открой **Git репозитории → Подключить репозиторий**. Укажи новый HTTPS-адрес с окончанием `.git`, ветку `main` и способ **HTTPS**. Имя пользователя — `x-access-token`. Токен вставь в отдельное поле **Пароль/Токен**. После сохранения выбери эту запись в настройках существующего бота и проверь журнал сборки. Команда запуска — `python main.py`.

Если сборка пишет `Repository not found` или `Authentication failed`, проверь новое имя, выбранный репозиторий и срок токена. При ошибке из Python Git-клонирование уже произошло. Тогда смотри первую строку с ошибкой запуска.

[Приватный репозиторий в BotHost](https://bothost.ru/docs/git-repository-access) · [Выбор ветки](https://bothost.ru/docs/repository-branch-deploy)

## Пользовательские переменные

| Переменная | Значение |
| --- | --- |
| `BOT_ENV_ONLY` | `1` включает настройки владельца через окружение. |
| `TGMAX_HOST` | `1` сохраняет режим с кабинетами. |
| `OWNER_ID` | Числовой MAX ID владельца. Сверь его с ID, на котором сейчас привязан кабинет владельца. |
| `ADMIN_IDS` | ID дополнительных администраторов MAX через запятую. |
| `DATA_DIR` | Путь к тому же постоянному диску, например `/app/data`. Если задан `TG_MAX_DIR`, используется он. |
| `BOT_SECRET`, `BOT_SECRET_SHA256` | Новый секрет запуска и его SHA-256. Добавь оба перед переключением на этот код. |
| `MAX_TOKEN` | Новый токен MAX. Код также принимает `MAX_BOT_TOKEN` и `BOT_TOKEN`, в этом порядке после `MAX_TOKEN`. |
| `MAX_CHANNEL_LINK` | Ссылка на свой канал в MAX. |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `SESSION_STRING` | Пара ключей приложения Telegram и новая строка сессии. `TG_API_ID` и `TG_API_HASH` имеют приоритет, если заданы. В этом режиме без строки сессии бот читает в публичном веб-режиме. |
| `SELLER_CONTACT` | Контакт, который бот показывает клиентам. |
| `LEGAL_OFFER_URL`, `LEGAL_PRIVACY_URL` | Ссылки на действующие документы. При совпадении полей приоритет у `OFFER_URL` и `PRIVACY_URL`. |
| `LEGAL_FORM`, `LEGAL_NAME`, `LEGAL_INN`, `LEGAL_OGRN`, `LEGAL_ADDRESS`, `SUPPORT_EMAIL`, `SUPPORT_PHONE` | Реквизиты, которые бот показывает клиентам. Перед включением режима перенеси используемые поля из панели. |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RECEIPT_EMAIL` | ID магазина, новый ключ и запасной адрес для чеков, если используется ЮKassa. |

Дополнительные настройки для уже подключённых интеграций — `VK_TOKEN`, `TIKTOK_COOKIES`, `GEMINI_API_KEYS`, `OPENROUTER_API_KEYS`, `DEEPSEEK_API_KEYS`. При необходимости укажи ссылки в `REFUND_URL` и `COOKIES_URL`. `MODE` и `PIP_*` относятся к настройкам хостинга и установки зависимостей.

Чтобы получить новую пару для запуска, выполни на своём компьютере:

```sh
python -c "import hashlib, secrets; s=secrets.token_urlsafe(32); print('BOT_SECRET=' + s); print('BOT_SECRET_SHA256=' + hashlib.sha256(s.encode()).hexdigest())"
```

Вставь результаты прямо в одноимённые поля панели. Отозванные токены и сессии могут остаться в старых копиях файлов, поэтому замени их в MAX, Telegram и ЮKassa. Приватность репозитория ограничивает новое скачивание исходников. Уже сделанные копии и публичные форки могут сохраниться. Доступ к рабочим аккаунтам определяется текущими ключами этих сервисов. Проверка `BOT_SECRET` останавливает запуск с ошибочной конфигурацией. При желании можно дополнительно собирать поставку через `build_obfuscated.sh`.

[Смена видимости GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)

## Проверка после выкладки

1. Проверь, что бот запустился с постоянного диска и владелец с заданным `OWNER_ID` открывает панель.
2. Открой «Условия» и сверь ссылки на документы. Если подключена ЮKassa, нажми «Проверить ЮKassa» в панели.
3. Проверь чтение Telegram на тестовом сообщении с отдельным PDF. В рабочем канале можно проверять после тестового.
4. При смене имени обнови отображаемое имя, логотип и публичную ссылку в самом MAX. Эти поля принадлежат сервису MAX.
