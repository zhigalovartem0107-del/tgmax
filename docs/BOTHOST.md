# Запуск на BotHost

Код обновляется из GitHub. Переменные владельца задаются в панели BotHost. Очередь, кабинеты и их настройки хранятся на постоянном диске. Перед сменой параметров сделай резервную копию текущей папки данных и проверь, куда она смонтирована.

## Приватный репозиторий

В GitHub создай fine-grained token владельца репозитория. Выбери только нужный репозиторий и разрешение **Contents → Read-only**.

В BotHost открой **Git репозитории → Подключить репозиторий**. Укажи новый HTTPS-адрес с окончанием `.git`, ветку `main` и способ **HTTPS**. Имя пользователя — `x-access-token`. Токен вставь в отдельное поле **Пароль/Токен**. После сохранения выбери эту запись в настройках существующего бота и проверь журнал сборки. Команда запуска — `python main.py`. Используй Python 3.11 или новее.

Если сборка пишет `Repository not found` или `Authentication failed`, проверь новое имя, выбранный репозиторий и срок токена. При ошибке из Python Git-клонирование уже произошло. Тогда смотри первую строку с ошибкой запуска.

[Приватный репозиторий в BotHost](https://bothost.ru/docs/git-repository-access) · [Выбор ветки](https://bothost.ru/docs/repository-branch-deploy)

## Обязательные переменные для MAX

Для копии с кабинетами заполни восемь полей: `BOT_PLATFORM=max`, `BOT_ENV_ONLY=1`,
`TGMAX_HOST=1`, `DATA_DIR`, `OWNER_ID`, `BOT_SECRET`, `BOT_SECRET_SHA256` и `MAX_TOKEN`.
Обычной копии для переноса в один MAX-канал без кабинетов нужен также `MAX_CHANNEL_LINK`.
Остальные поля включают отдельные функции. Значения из скриншотов с ключами нужно заменить.

## Полный список переменных для настройки MAX

| Переменная | Значение |
| --- | --- |
| `BOT_PLATFORM` | `max` запускает режим MAX. Это значение по умолчанию. |
| `BOT_ENV_ONLY` | `1` включает настройки владельца через окружение. |
| `TGMAX_HOST` | `1` сохраняет режим с кабинетами. |
| `OWNER_ID` | Числовой MAX ID владельца. Сверь его с ID, на котором сейчас привязан кабинет владельца. |
| `ADMIN_IDS` | ID дополнительных администраторов MAX через запятую. |
| `DATA_DIR` | Путь к тому же постоянному диску, например `/app/data`. Если задан `TG_MAX_DIR`, используется он. |
| `BOT_SECRET`, `BOT_SECRET_SHA256` | Новый секрет запуска и его SHA-256. Добавь оба перед переключением на этот код. |
| `MAX_TOKEN` | Новый токен MAX. Код также принимает `MAX_BOT_TOKEN` и `BOT_TOKEN`, в этом порядке после `MAX_TOKEN`. |
| `MAX_CHANNEL_LINK`, `MAX_CHAT_ID` | Ссылка на свой канал в MAX и его числовой ID при необходимости. |
| `TG_PHONE` | Номер Telegram-аккаунта, если используется соответствующий сценарий подключения. Строковой сессии номер для запуска не нужен. |
| `TG_PROXY`, `TREND_PROXY` | Прокси для публичных страниц Telegram и для поиска трендов. Задавай только при необходимости. |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `SESSION_STRING` | Пара ключей приложения Telegram и новая строка сессии. `TG_API_ID` и `TG_API_HASH` имеют приоритет, если заданы. В этом режиме без строки сессии бот читает в публичном веб-режиме. |
| `SELLER_CONTACT` | Контакт, который бот показывает клиентам. |
| `LEGAL_OFFER_URL`, `LEGAL_PRIVACY_URL` | Ссылки на действующие документы. При совпадении полей приоритет у `OFFER_URL` и `PRIVACY_URL`. |
| `LEGAL_FORM`, `LEGAL_NAME`, `LEGAL_INN`, `LEGAL_OGRN`, `LEGAL_ADDRESS`, `SUPPORT_EMAIL`, `SUPPORT_PHONE` | Реквизиты, которые бот показывает клиентам. Перед включением режима перенеси используемые поля из панели. |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RECEIPT_EMAIL` | ID магазина, новый ключ и запасной адрес для чеков, если используется ЮKassa. |
| `PAYMENT_INSTRUCTIONS` | Необязательный текст ручной оплаты, видимый клиентам. |

Дополнительные настройки для уже подключённых интеграций — `VK_TOKEN`, `TIKTOK_COOKIES`, `GEMINI_API_KEYS`, `OPENROUTER_API_KEYS`, `DEEPSEEK_API_KEYS`. При необходимости укажи ссылки в `REFUND_URL` и `COOKIES_URL`. `WELCOME_VIDEO_PATH` и `WELCOME_VIDEO_URL` задают приветственное видео.
`MODE`, `PIP_DEFAULT_TIMEOUT` и `PIP_RETRIES` относятся к настройкам BotHost и установки зависимостей.
`ADMIN_CODE` и `HOST_CODE` предназначены для старой схемы привязки. В режиме MAX с кабинетами и `BOT_ENV_ONLY=1` используй `OWNER_ID` и `ADMIN_IDS`.
При нестандартной установке `MAX_API_URL` задаёт адрес API MAX, `TZ` — часовой пояс, `TRENDS` — режим трендов.
Для ИИ дополнительные настройки провайдеров — `GEMINI_API_URL`, `GEMINI_MODEL`,
`OPENROUTER_API_URL`, `OPENROUTER_MODEL`, `OPENROUTER_IMAGE_MODEL`, `DEEPSEEK_API_URL` и `DEEPSEEK_MODEL`.
Служебные параметры для отдельных ботов кабинетов (`TGMAX_CLIENT`, `TGMAX_HUB`, `TGMAX_HUB_KEY` и другие) задаёт сам проект.

Чтобы получить новую пару для запуска, выполни на своём компьютере:

```sh
python -c "import hashlib, secrets; s=secrets.token_urlsafe(32); print('BOT_SECRET=' + s); print('BOT_SECRET_SHA256=' + hashlib.sha256(s.encode()).hexdigest())"
```

Вставь результаты прямо в одноимённые поля панели. Отозванные токены и сессии могут остаться в старых копиях файлов, поэтому замени их в MAX, Telegram и ЮKassa. Приватность репозитория ограничивает новое скачивание исходников. Уже сделанные копии и публичные форки могут сохраниться. Доступ к рабочим аккаунтам определяется текущими ключами этих сервисов. Проверка `BOT_SECRET` останавливает запуск с ошибочной конфигурацией. При желании можно дополнительно собирать поставку через `build_obfuscated.sh`.

[Смена видимости GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)

## Проверка после выкладки

1. Проверь, что бот запустился с постоянного диска и владелец с заданным `OWNER_ID` открывает панель.
2. Открой «Условия» и сверь ссылки на документы. Если подключена ЮKassa, нажми «Проверить ЮKassa» в панели.
3. Проверь чтение Telegram на тестовом сообщении с отдельным PDF. В рабочем канале можно проверять после тестового.
4. При смене имени обнови отображаемое имя, логотип и публичную ссылку в самом MAX. Эти поля принадлежат сервису MAX.


## Запуск Telegram-бота из этого же проекта

Создай в BotHost отдельную копию из той же ветки. Команда запуска — `python main.py`.
Путь `/app/data` подходит, если каждый контейнер имеет свой постоянный диск. Если диск общий,
выбери отдельный каталог Telegram. Каждый Telegram-токен должен использовать только один процесс
с long polling. При ошибке 409 проверь вторую копию и существующий webhook.

| Обязательная переменная | Что указать |
| --- | --- |
| `BOT_PLATFORM` | `telegram` |
| `DATA_DIR` | Отдельная постоянная папка Telegram-бота, например `/app/data`. |
| `BOT_SECRET`, `BOT_SECRET_SHA256` | Пара для запуска. Для второй копии можно сгенерировать отдельную пару. |
| `TELEGRAM_BOT_TOKEN` | Токен нужного Telegram-бота из BotFather. |
| `TELEGRAM_OWNER_ID` | Твой числовой ID в Telegram. Он может отличаться от MAX ID. |
| `TELEGRAM_CHANNEL_ID` | Числовой ID Telegram-канала или его публичное `@имя`. |

Дополнительно можно указать `TELEGRAM_ADMIN_IDS` через запятую и `TELEGRAM_SUPPORT_CONTACT` для
команды поддержки. Она также читает `SELLER_CONTACT`. Документы и реквизиты используют те же
`LEGAL_*`, `*_URL` и `SUPPORT_*` поля. Telegram-режиму не нужны MAX-токен, ключи Telethon, `SESSION_STRING`
или настройки ЮKassa. Токен BotFather управляет ботом, а `SESSION_STRING` авторизует отдельный аккаунт
Telegram для чтения источников в MAX-версии.

Добавь Telegram-бота в администраторы своего канала с правом публикации. Команда
`python main.py --check` проверяет токен и право публикации без отправки сообщения в канал.

В личном чате с ботом используй `/post`, пришли содержимое или перешли публикацию с PDF либо другими
вложениями. После получения всех частей нажми «Предпросмотр» или «В очередь». Пример отложенной
публикации — `/post 30`. Для рекламы используй `/ad` и при необходимости `/link https://example.org`.
Команда `/queue` показывает статусы, `/cancel 3` отменяет публикацию №3 до отправки.
Если в очереди появился статус «проверь канал», сначала проверь канал перед повторной постановкой.

Чтобы автоматически переносить новые публикации из своих Telegram-каналов, задай
`TELEGRAM_SOURCE_IDS` — числовые ID источников через запятую. Добавь бота в каждый канал-источник,
к которому у тебя есть разрешение на доступ. Старые публикации таким способом не загружаются.
Источники, к которым у Bot API нет доступа, можно пересылать в редактор вручную.
Мониторинг трендов, кабинеты и подключение ЮKassa доступны в режиме MAX.
